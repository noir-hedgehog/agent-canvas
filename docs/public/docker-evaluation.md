# Docker 发行评估

状态：暂缓。本轮仅发布 GitHub Pages 演示和本地版，尚未实现或发布容器版。

AgentCanvas 当前是单个 Node.js 24 服务、SQLite 数据库、受管理图片和本地文件引用，MCP 使用 STDIO 适配器。Docker 的价值主要是已有容器环境下的可重复部署，不是降低普通桌面用户的首次安装成本。

| 使用场景 | 判断 |
| --- | --- |
| 个人服务器或 NAS 长期运行 | 有价值，适合作为可选自托管包 |
| 已有 Docker、Agent 与画布位于同一主机 | 可行，但需明确 MCP 和目录挂载配置 |
| 普通电脑用户首次使用 | 优先本地发行包，避免额外依赖 Docker |
| 多人公网服务、跨设备远程 Agent | 超出容器打包范围，需要单独设计身份、授权及远程接入 |

## 实施成本

- 服务监听地址要允许容器端口转发，主机映射仍默认限制本机访问。
- 数据库、托管截图和凭据必须放入持久化数据目录；引用文件使用独立工作区挂载。
- 当前绝对路径会在容器内变化，不能直接沿用宿主机文件引用；需要明确路径约定和迁移说明。
- 当前 MCP 配置包含本机命令路径。容器版需提供实际可执行的容器 STDIO 接入命令；服务器上的容器不会自动成为桌面 Agent 的远程 MCP。
- 需要验证重建后数据保留、文件读取、截图资产、MCP 读写和授权边界。

## 推荐范围

若以个人服务器 / NAS 为目标，仅实现单服务 Compose、持久卷、工作区挂载、健康检查和备份说明。沿用同一份代码和 SQLite，不引入独立数据库、Redis、Kubernetes 或另一套产品界面。

Docker 数据卷独立于容器生命周期；需要与宿主机共同访问的引用文件更适合绑定挂载。参考 [Docker volumes](https://docs.docker.com/engine/storage/volumes/) 和 [bind mounts](https://docs.docker.com/engine/storage/bind-mounts/)。
